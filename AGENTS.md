# Repository conventions

## Structure

- Keep the project overview and submission status in `README.md`.
- Store final UI screens in `assets/screens/`.
- Store project documentation in `docs/`.
- Use lowercase kebab-case for new Markdown documents.
- Use two-digit numeric prefixes for ordered screen assets.

## Documentation

- Do not mark planned work as complete.
- Record the tool, prompt, observed result, and follow-up correction for generated assets.
- Keep external references and licensing information traceable.
- Update the README checklist whenever deliverables change.

## Git

- Do not commit credentials, browser sessions, temporary files, or generated caches.
- Group one logical deliverable per commit.
- Use concise imperative commit messages.
