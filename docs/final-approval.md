# 최종 승인 체크

## 승인 기록

- 승인일: 2026-08-13
- 승인 범위: 저장소 문서, UI 화면 3장, 로컬 클릭형 프로토타입, 자동 검사
- 승인 상태: **로컬 산출물 최종 승인**
- 예외: Figma 프로젝트 및 공유 URL은 외부 계정 작업으로 별도 등록 필요
- 공개 접근: Public 저장소와 GitHub Pages 프로토타입의 HTTP 200 응답 확인

## 판정

**로컬 산출물 최종 승인 / Figma 제출 항목 보류**

로컬 산출물, 문서, UI 이미지 3장, 클릭형 프로토타입과 자동 테스트는 준비되었습니다.
다만 실제 Figma 프로젝트와 공유 링크가 없어 최종 제출 완료로 표시할 수는 없습니다.

## 승인 완료 항목

- 사용자 문제와 핵심 UX 흐름 정의
- 모바일 UI 화면 3장과 일관된 시각 스타일
- 초안, 수정, 최종 프롬프트 및 개선 근거 기록
- 디자인 시스템, 출처, 윤리·안전 기준 문서화
- 오늘의 운동 → 운동 진행 → 완료 및 보상 화면 순환
- 일시정지/계속하기, 이전/다음, 키보드 이동 구현
- 이미지 로딩과 프로토타입 자동 검증 통과

## 최종 승인 전 필수 작업

- [ ] Figma에서 3개 화면을 프레임으로 생성
- [ ] 텍스트, 아이콘, 주요 컴포넌트 후가공
- [ ] Hotspot 연결 후 Present 모드에서 순환 확인
- [ ] 보기 권한이 설정된 Figma 공유 URL을 README에 등록

위 네 항목을 완료한 뒤 README 체크박스를 갱신하면 최종 승인 상태가 됩니다.
Figma 제작자는 [`figma-handoff.md`](figma-handoff.md)의 프레임, 좌표, 연결 명세를
그대로 적용하고, 제출 설명은 [`submission-note.md`](submission-note.md)를 사용합니다.

## 승인 검사 실행

프로젝트 루트에서 다음 명령을 실행합니다.

```text
node scripts/final-check.cjs
```

검사는 필수 파일, UI 이미지 파일 크기, 프로토타입 전체 흐름과 README의 미완료
항목을 확인합니다. 출력이 `결론: 최종 승인 가능`이면 제출할 수 있습니다.

## 제출 직전 수동 확인

1. README의 세 화면 이미지가 정상 표시되는지 확인
2. Figma 공유 URL을 로그아웃 상태 또는 시크릿 창에서 열어 보기 권한 확인
3. `5분 운동 시작 → 다음 → 내일 운동 확인` 흐름을 한 번 순환
4. 저장소에 계정 정보, 임시 파일 또는 브라우저 세션이 없는지 확인
5. 최종 변경 사항을 하나의 논리적 커밋으로 정리
